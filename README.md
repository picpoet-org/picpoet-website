# 图赋 / PicPoet website

Vue 3 + Vite 纯前端网站，维护产品说明、下载与在线创作界面。BFF、登录会话与业务代理全部由相邻 `picpoet-server` 的 Go 服务实现，本仓库不包含后端运行服务。简体中文品牌为 **图赋**，其余语言品牌为 **PicPoet**。

## 正式发布地址

公开地址在 `deployment.json` 维护：

| 用途 | 地址 |
| --- | --- |
| 官网 | `https://picpoet.jqknono.com` |
| 官网及新版 Android 主清单 | `https://downloads.nullprivate.com/picpoet/release/stable.json` |
| 备用清单（同一 R2 桶） | `https://downloads.jqknono.com/picpoet/release/stable.json` |

PicPoet 的安装包与正式发布 JSON 由客户端标签流水线写入 R2 的 `picpoet/release/`。客户端版本、更新说明、文件大小和 SHA-256 以 [R2 稳定清单](https://downloads.nullprivate.com/picpoet/release/stable.json) 为准；安装包路径为 `<CDN 根路径>/<平台>/<版本>/<文件名>`。网站无需随客户端发版修改或重新部署。调整公开地址时，同步客户端配置 `../picpoet-app/android/packaging/release-config.json` 及 ESA `connect-src`、R2 CORS。

## 本地预览

要求 Node.js 22.13+，命令工作目录为 `picpoet-website/`：

```bash
npm ci
npm run dev
```

打开 <http://127.0.0.1:8080>。Vite 实时预渲染 Vue 组件并提供热更新；官方联调入口 <http://127.0.0.1:18090> 同样使用 Vite，改源码即可看到更新。`/web-api` 与邀请深路径仅转发到 `VITE_API_PROXY_TARGET`（默认 `http://127.0.0.1:18081`）的 Go 服务，保留浏览器 Host/Origin。后端应允许当前开发页面来源。仅查看公开内容时无需启动业务后端。`npm run build` / `public:sync` 生成 `public/`，`npm start` 使用 Python 3 静态预览该产物，不提供业务代理。

次数由共享会话逻辑自动维护：进入已登录页面、回到前台或网络恢复时查询，购买到账及创作完成后更新；不定时轮询次数，个人中心不提供手动刷新按钮。暂时查询失败时保留上次次数并显示错误，下一次上述事件触发后恢复；其他设备的变化在回到页面时同步。

## Vue 与多语言结构

- `src/views/`：首页、说明、定价、下载、创作、作品、账户、登录八个页面。
- `src/components/`：共用页头、页脚、响应式菜单、会话提示、二维码、订单和发布信息。
- `src/composables/`：会话取消与账户世代、图片与生成任务、历史图片和对话框、订单幂等与限次轮询、发布清单。
- `src/locales/zh-cn/`：简体中文文案源；内容、SEO、错误和业务提示均按键读取。其他字典由 agent 结合界面与业务语境直接维护。
- `shared/`：复用图片压缩、任务协议、诗词排版、本地字体与清单校验；旧 DOM 页面控制器已由 Vue 替代。
- `scripts/sync-public.mjs`：从同一套 Vue 组件预渲染完整 HTML，再挂载客户端；Vite 维护带内容 hash 的 JS/CSS。`public/` 与 `.build/` 是忽略的生成目录。

保留根目录 `.html` 地址和 `/pages/` 兼容入口。非简体中文使用 `/zh-hk/`、`/zh-tw/`、`/en-us/`、`/ko-kr/`、`/ja-jp/` 路径；共享页头按语言生成站内地址，保留当前页面与登录目标。每个已交付语言均有对应 `lang`、canonical 和 hreflang。界面语言选择不写 Cookie 或浏览器存储；界面语言、标签语言与 `poemLanguage` 分开。个人中心的“创作偏好”仅展示诗词体裁、用字、词牌／字数与韵书，组内宽屏两列、窄屏单列。网站统一关闭照片信息生成：默认值和读取旧账户偏好时均将 `photoInfo` 视为 false，隐藏照片信息开关、标签语言及构图建议配置；提交固定发送 `photoInfo=false`、`suggest=false`，不执行照片描述、标签或构图建议请求。服务器旧偏好不作批量改写，既有历史作品不变。选择“不生成诗词”时禁用生成并提示选择诗词体裁。App 与生成服务旧客户端的默认行为不变。生成服务须已应用 `20261116_photo_info.up.sql`，支持任务快照、重启恢复及幂等重试。

偏好通过 BFF 的 `GET/PUT /web-api/preferences` 同步到账户服务 `GET/PUT /api/v1/picpoet/preferences`，以 JWT 中的用户 ID 存入 `user-dashboard` 的 `picpoet_preferences` 表（迁移 000015，支持 PostgreSQL 与 SQLite）。浏览器不能指定其他账号；最后一次成功写入覆盖整份配置。首次读取账户尚无配置时，将当前浏览器旧版 `picpoet:creation:v1:<account-id>` 偏好导入；`initialize: true` 使用原子插入，已有账户配置不被其他浏览器旧数据覆盖。无旧配置的新账户默认使用简体诗词（`poemLanguage=zh`）、中华新韵（`rhymeStandard=zhonghua`）、词（`poem=""`、`ci=auto`，自动选择词牌），不随界面语言切换。已有账户保存的偏好与可迁移的旧浏览器偏好保持不变；网站诗词用字默认值独立于 App／原生参数默认值。

`picpoet:creation:v2:<account-id>` 仅缓存服务器确认过的配置，不保存凭据。登录、页面恢复前台和新任务提交前重新读取账户配置；跨浏览器登录同一账号即可读取，已打开的其他浏览器在恢复前台或提交新任务时更新，不做实时推送。App 设置暂独立。读取失败时显示重试并阻止修改或新任务；保存失败保留当前页待同步修改，明确提示未保存，可重试，离开页面后未保存修改会丢失。正常读取和保存成功后不显示说明文字；失败时仍显示提示和重试入口。缓存写入失败不影响服务器保存成功。新任务固定提交时的全部参数，重试保持原快照；恢复任务只查询，不重新提交。关闭诗词时显式发送空 `poem`、`ci`，结果与历史仍显示照片信息、标签和构图建议，仅有诗词时提供分享图。历史详情读取服务端独立归档的 `metadata`，按实际内容展示；全部为空时隐藏照片信息区，不显示空标题。服务端须先执行 `20261115_history_metadata.up.sql` 并更新版本；该迁移只补齐仍可恢复的有效历史，已清理的旧结果无法恢复。

历史图片在当前作品列表生命周期内共享内存缓存：列表、详情和并发加载复用同一图片请求及 Blob URL，关闭后再次打开详情不重复下载。详情文字与权限仍每次向服务端确认；删除／过期响应清除对应图片，刷新列表、退出、切换账号或离开页面释放缓存。图片不写入持久浏览器存储或公共 CDN，首次加载继续使用带凭证的 no-store 请求。

历史列表采用照片、可点击标题、限行诗词摘要和时间的层级，完整内容在详情中阅读，不在卡片内嵌滚动区域。卡片在照片加载期间或加载失败时显示山景占位图形；照片就绪后在原位显示，不改变卡片布局。创作时间与自动删除时间作为次级信息置于每张卡片底部分隔区，窄屏自动换行；详情将同一时间信息放到正文之后、操作区上方，不再占据标题与图片之间的位置。自动删除时间表示服务端历史保留期结束，不改变实际清理规则。详情保留标签原文，使用低强调标签样式；构图建议仅将明确的项目符号整理为语义列表，普通段落保留原文，不解析模型 HTML。分享操作与永久删除分区，删除仍需确认。

词牌使用一体化可搜索选择框：点击后在框内搜索简体或繁体名称，从下拉结果确认；支持方向键、Enter 选择，Escape／移出焦点取消未确认的搜索。搜索文本本身不保存为偏好，“自动选择”始终可选。下拉列表内的滚动条支持点击和拖动，输入框因操作滚动条失焦时保持展开；点击控件外部或键盘离开时关闭。

`shared/generation-options.json` 是 Rust schema 与完整词牌目录的已提交快照。参数源变更后执行 `node scripts/sync-generation-options.mjs`；该开发命令需要相邻 Rust/App 仓库和 App 已解析的 Dart/pinyin 依赖，通过同一简繁转换维护词牌名称。普通网站构建不依赖相邻仓库。

窄屏展开导航采用两列三行布局，五个页面入口之后的右下角为语言选择，导航与语言控件保持等高、按视觉顺序键盘访问。页头语言选择与创作偏好（诗词用字、体裁、字数、韵书）保留原生 `select`，共用弹层兼容样式。浏览器支持 `appearance: base-select` 时，两类选择框在所有屏宽均使用浏览器顶层选择器跟随控件定位，避免嵌入式浏览器的系统弹窗坐标漂移；不支持此特性的浏览器沿用系统选择器。偏好控件保留已有箭头，不重复显示浏览器箭头；词牌搜索框不受影响。语言切换、偏好自动保存与键盘操作仍由原有逻辑和原生控件处理。

### 六语言翻译与验证

目标语言为简体中文、香港繁体中文、台湾繁体中文、英文、韩文、日文。导航只展示完整字典的语言，不使用占位译文。

本工程不再使用 project-translator-cli，多语言由 agent 直接编辑 `src/locales/` 下的 JSON 字典维护，不需要翻译服务凭据。新增或修改简体中文源文时，在同一变更中同步香港繁体、台湾繁体、英文、韩文和日文；仅修改相关键，避免整文件重译及无关文案变化。结合页面用途审校语义、术语与地区表达，保持业务事实、协议值、链接及占位符不变。

翻译完成后验证网站产物：

```bash
npm run locales:check  # 六种语言的文件、键、占位符和品牌检查
npm run build:all      # 严格六语言预渲染
```

各语言必须保持相同的键、对象结构、数组长度和 `{brand}`、`{count}` 等占位符，不使用空值、源文占位或删除字典绕过校验。简体中文品牌为“图赋”，其他语言为“PicPoet”，通过 `{brand}` 统一插值。完整性检查不能代替翻译语义审校；正式六语言交付以完整性检查、`build:all` 和六语言浏览器验收成功为准。普通 `npm run build` 可用于阶段性构建，完整交付仍使用 `build:all`。

## 页面

登录账户购买由 Dashboard 服务端复用创建时间未超过 5 分钟的未支付订单，匹配同账户、套餐、价格、币种、次数、支付方式与交付方式。再次点击不延长复用窗口；已支付、已关闭和超时订单不复用。数据库事务串行处理同账户的并发创建；网页按返回订单 ID 去重并定位到第一页。匿名购买继续使用原 requestId 幂等规则。

“我的订单”标题、折叠标记与刷新按钮在同一行垂直居中；刷新按钮独立操作，不切换折叠状态。订单金额与支付入口组成居中对齐的操作组，窄屏移至订单信息下方并可换行，避免挤压订单号。选择“点击支付”会在新窗口或标签页打开收银台，原订单页保留；扫码支付仍在订单内展示。

- `/index.html`：产品首页
- `/docs.html`：使用说明，分别说明网站在线创作与客户端 App 的当前能力
- `/pricing.html`：定价
- `/downloads.html`：下载资源
- `/create.html`：选图、在线创作、可附照片的诗词分享 PNG，仅展示轻量次数提示
- `/works.html`：我的作品，历史缩略图、详情、下载和删除
- `/account.html`：个人中心，账户信息、剩余次数、套餐购买与订单
- `/login.html`：手机号或邮箱登录、注册；邮箱方式保留验证流程，成功后回到原目标页

主导航统一为「首页 / 在线创作 / 我的作品 / 下载客户端 / 个人中心」。同源、同语言的已知站内页面由 Vue Router 导航，共用应用级内存会话；切换创作、作品、个人中心和公开页不会重新检查登录。保留 `.html`、无扩展名直达及 `/pages/` 兼容入口的静态预渲染；跨语言、外链、下载与新窗口保持原生导航。路由同步标题、描述、canonical、语言替代链接、焦点与前进后退滚动位置。

应用首次可见时检查一次会话；恢复前台或网络恢复时，成功校验后五分钟内复用，失败按 30 秒起、最多五分钟退避，只响应事件，不做定时心跳。首次未知状态用局部骨架占位，后台校验不清空内容；暂时网络失败不视作退出，明确 401 才清理身份。并发会话请求合并，登录成功直接复用返回身份并站内回跳。退出及换号用 BroadcastChannel 通知其他标签页清理旧状态；浏览器缓存恢复按需重查，不强制整页刷新。前端仅保存展示状态，业务权限与令牌刷新仍由 BFF 负责，HttpOnly Cookie 与七天不活动到期规则不变。

公共介绍页面可独立浏览，账号服务暂不可用不影响公开内容。各页只加载自身业务数据，页面请求取消域与共享账户取消域分离：离开页面取消其请求、释放照片与 Blob，退出或换号取消所有旧账号任务。登录 `returnTo` 只允许已知站内页面及指定锚点，不接受外站 URL；跨页不会保存密码或业务凭证到浏览器存储。

创作中的图片与尚未下载的分享图仍只在当前页面内存；离开或切换语言前请保存作品，进行中的服务端任务可返回创作页恢复。历史作品在独立作品页查看。浏览器正向测试直接验证预渲染的真实 Vue 页面及登录回跳，不维护另一套测试专用业务页面。

创作等待区展示一条带轻呼吸圆点的进度提示与公版诗句，每 3 秒用约 450ms 的淡入/轻移过渡切换，按最长诗句保留高度。悬停、键盘聚焦、页面进入后台时停留当前诗句；启用“减少动态效果”时，诗句和进度圆点保持静态。键盘/读屏用户可访问暂停控制，普通界面保持简洁。暂停自动更新与任务编号收纳在“查看创作详情”，暂停只影响本页查询，不取消服务端创作。原有查询次数上限保持不变。

创作完成后仅显示分享图，不重复展示一份正文；下载 PNG 旁可“拷贝诗词”（标题、词牌、正文），并保留读屏文本。剪贴板不可用时提供可选中的文字；绘图失败时正文仍可阅读与复制。“重绘分享图”入口已移除，历史作品可重新导出。

作品详情与创作页的备用文字视图采用标题、词牌、正文逐行居中，保留原有换行和段落空行，与分享 PNG 的排版方向一致。详情打开时按文字内容加载与 PNG 共用的同源霞鹜文楷分片，不等待导出操作；字体加载失败时保留系统字体供阅读，不阻塞照片与操作。日期、按钮和二维码选项继续使用界面字体，作品列表保持原有排版。

### 手机号账号与登录锁定

登录页使用统一的“邮箱或手机号”输入框，按输入自动选择认证方式；格式、密码和锁定规则仅在对应校验失败时提示。手机号按 `1[3-9][0-9]{9}` 校验，接受 `+86` / `0086` / `86` 前缀并统一保存为 11 位；只校验格式，不核验号码归属。注册时两次输入相同密码，至少 6 个字符，无大小写或符号组合要求；密码支持粘贴、密码管理器和显示/隐藏，继承 bcrypt 最多 72 字节边界。邮箱密码继续至少 8 位并验证邮箱。

手机号注册后，用手机号和刚设置的密码登录。**密码只能通过已绑定邮箱找回，请尽早在个人中心绑定。** 个人中心使用当前会话向 `POST /web-api/account/email/request` 提交 `{email}`，收到 `{otpSent:true}` 后再提交 `POST /web-api/account/email/confirm` 的 `{email,otp}`。验证码为六位数字，可重发，也可编辑待验证地址；邮件可能进入垃圾邮件。验证成功后 BFF 更新会话并返回 `{user}`。首次绑定不需要当前密码。手机号账户以非空 `email` 和 `emailVerified=true` 显示找回邮箱及“已验证”标记；邮箱登录账户直接在身份栏显示验证状态，不重复展示找回邮箱。

两类账户均可在个人中心选择“更换邮箱”。用当前密码向 `POST /web-api/account/email/change/request` 提交 `{email,password}`，再向 `POST /web-api/account/email/change/confirm` 仅提交 `{email,otp}`。密码不保存在页面状态或浏览器存储中；重新发送需重新输入当前密码。确认前可取消，原邮箱仍有效；以确认接口返回的 `{user}` 更新当前身份，并通知其他标签页重新获取资料。邮箱登录账户之后使用新地址登录，手机号账户的登录号不变。错误密码（`403 CURRENT_PASSWORD_INCORRECT`）只提示重新输入，不会退出当前会话；真正的 `401` 仍按会话失效处理。

登录模式的“忘记密码？”跳转到 Dashboard 既有 `/forgot-password` 页面，不传手机号、邮箱或会话凭证。官网使用 `deployment.json` 的 `dashboardWebUrl`；本地／预览通过 `VITE_DASHBOARD_WEB_URL` 显式指定同环境 Dashboard 网页地址（官方联调启动器提供），未配置则不显示入口，不引导测试账号到生产。

所有账号的密码登录共用服务端连续失败计数：前 50 次未触发账号锁，第 51 次锁定 1 小时。锁中包括正确密码在内的新密码登录均返回 `423 ACCOUNT_LOCKED`，重复请求不延长锁定；成功登录或锁定到期后重新计数。状态持久化在 Dashboard 数据库，两个认证入口共享，刷新网页或重启服务不能清除。已登录会话的 refresh 不属于新密码登录，继续工作且不清计数。BFF 原有按 IP/账号的请求限流独立保留，可能先返回 429，不能等同账号锁定。

网站 BFF 白名单接受 `{phone,password,confirmPassword,invitationCode?}` 注册及 `{phone,password}` 登录；邮箱请求保持兼容。确认密码与认证凭证不会进入浏览器响应或持久存储，锁定错误使用固定文案，不透传上游错误正文。手机注册继续支持邀请奖励。

上线需升级 Dashboard 并应用 `000014`（保留已有 `000013`），再重启网站 BFF。SQLite 空库与既有 12/13 版本自动升级到 14，测试使用临时数据库；PostgreSQL 的行锁、实际迁移与线上验收需另行执行。规则详见 [Dashboard 手机号认证契约](../../user-dashboard/docs/phone-auth.md)。本次未迁移真实数据库、未重启联调栈、未修改 Flutter 客户端。

### 分享邀请与获赠次数

创作页与历史作品详情的“附加邀请二维码”统一放在生成／下载按钮下方的独立次级行，使用次级字号与常规字重；宽窄屏均保持主要操作在前、分享选项在后，视觉顺序与键盘顺序一致，保留完整点击区域、默认勾选与取消确认行为。

创作和历史作品的 PNG 在下方独立留白区附个人邀请二维码，二维码背景与分享图使用同一纸色、码点复用印记的深朱砂色（`accent-dark`），避免纯白底块割裂画面；保持四模块静区、整数像素与不透明绘制。支付二维码仍使用默认黑白配色。二维码本地绘制，不上传作品到第三方。个人中心“我的邀请链接”与分享图二维码共用同一链接来源，由当前页面的 `window.location.origin`、服务端自动生成的 `user.id` 与 `balance.referral.invitationCode` 组成。测试页面保留当前协议、主机及端口，不跳转生产；生产页面自然使用生产域名。预渲染期间不生成个人邀请链接。生产示例：

```text
https://picpoet.jqknono.com/{user.id}/invite_code={invitationCode}
```

本地 `http://127.0.0.1:18090` 页面生成同源邀请地址；手机扫码联调时，应从手机可达的局域网地址打开网站再生成分享图，回环地址不能用于其他设备访问。已经下载的旧分享图不会自动更新，需要重新生成。

路径中的用户 ID 稳定且不包含邮箱；归因仍以服务端邀请码为准，不依赖显示用户名。Go BFF 只对合法邀请路径跳转到固定的注册页面，自动填入邀请码；登录回跳白名单保持原有边界。语言切换保留有效邀请码。余额/邀请码暂不可用时允许导出无邀请二维码的作品，并明确提示，避免影响诗词保存。

所有注册入口的新用户携带有效邀请码、创建账户成功后，Dashboard 在注册事务内给邀请人发放 **3 次可累计创作额度**，不等邮箱验证，不设每日上限；同一新账号仅发一次，首次生成不重复发奖。此规则会给未验证邮箱的注册发奖，沿用现有注册限流，正式运营需持续监测邀请滥用。历史邀请继续旧规则，不回收或重算已到账额度。

个人中心将账户／余额与邀请获赠分为两块，宽屏并排、窄屏上下排列。邀请操作仅保留“复制邀请链接”；剪贴板不可用时展示并选中可复制的完整链接，切换账户后清除旧反馈。已登录用户访问登录／邀请页时显示当前账户与明确的继续目的地；邀请页说明奖励仅适用于新用户注册，不自动退出或跳转，也不因预览产生奖励。

个人中心和创作页按账户服务的 `remaining.gifted`、`remaining.purchased` 展示余额：“赠送剩余”包含每日官方额度、人工赠送与邀请奖励中当前可用的次数；“购买剩余”只包含购买或购买兑换后仍可用的次数，不重复计算赠送。个人中心另用 `referral.totalGrantedCredits` 展示历史累计邀请获赠，消费后不减少。旧后端缺少相应统计时显示占位，不将未知状态冒充 0。

累计获赠下方提供默认收起的“已邀请用户”。每次展开时，网站通过需登录的 `GET /web-api/invitations` 读取 Dashboard 的 `GET /api/v1/invitations`，复用 JWT 续期和服务端用户身份校验，不接受浏览器指定邀请人；仅返回记录 ID 与完整邮箱，不返回用户名或手机号。无邮箱记录显示“手机号用户”，加载失败可重试，成功空列表与接口失败分别提示；退出或切换账户清除列表。记录沿用 Dashboard 成功邀请的统计口径，不能将列表人数乘以当前奖励额度替代累计实际获赠。此功能需更新并重启网站 BFF，无需数据库迁移。奖励迁移及规则说明见 [Dashboard 邀请奖励说明](../../user-dashboard/docs/picpoet-referral-registration-rewards.md)。

**交付边界：** Dashboard 需升级并应用 `000013`，网站 BFF 需重启加载邀请路由。纯静态 ESA 部署不处理动态邀请路径，正式域名需将邀请深路径和 `/web-api/*` 路由到 Go BFF；只上传 `public/` 不能完成注册获赠。以上为代码与隔离测试能力，未自动修改线上或联调数据库。

## 网页版创作（本地验收）

网页版复用 Dashboard 的 Picpoet 邮箱注册／OTP 验证、账户及额度，通过官方异步任务生成诗词。分享卡在浏览器以文楷绘制，沿用客户端的纸色、1080px 宽的诗板和品牌底纹，可附照片。文楷使用 ZSFT 发布的霞鹜文楷 v1.530 Regular 网页分片，缓存在 `assets/fonts/lxgw-wenkai/`；绘制时只启用当次文字覆盖的同源 woff2，不请求外部字体，也不再下载完整 TTF。选图后仅在本机读取原文件名与照片时间、缩小并重新编码为 JPEG；点击生成才上传。上传图片不含原图 EXIF，原文件名及时间作为独立可选字段发送，不收集 GPS、相机型号等其他 EXIF 信息。历史启用后，新提交的账户官方成功任务保存压缩照片与诗词 90 天，可提前永久删除；不保存原图、不回填旧任务。是否已保存以历史接口记录为准，需要长期保留的作品请下载。

工作目录 `picpoet-website/`，Node.js 22.13+。先启动启用了网页接口的 Go 服务，然后启动前端：

```bash
VITE_API_PROXY_TARGET=http://127.0.0.1:18081 npm run dev:web
```

打开 <http://127.0.0.1:18090/create.html>。`dev:web` / `dev:web:official` 都是 Vite 前端入口，不再启动 Node BFF。Go 服务必须允许开发页面的 Host/Origin，后端启动配置见相邻 [picpoet-server](../picpoet-server/README.md)。

一键联调继续使用 `npm run dev:stack`（无 Flutter GUI）或 `npm run dev:stack:gui`，由 `picpoet-app/official-dev.sh` 统一管理。网站进程只运行 Vite；登录、额度、订单和生成转接由 Go 服务执行。查看状态与停止使用：

```bash
bash ../picpoet-app/official-dev.sh status
bash ../picpoet-app/official-dev.sh stop
```

账户和额度属于官方联调的 debug 数据库，不是生产库；注册验证码在联调 Mailpit `http://127.0.0.1:18025` 查看。网页支持本机和配置的局域网入口；不要混用未允许的 `localhost`。

- 浏览器仅持有 HttpOnly 会话 Cookie，不接收 JWT、刷新令牌或业务凭证。会话持久化、七天滑动续期、限流和上游超时均由 Go BFF 维护，配置与运维说明归属 server 仓库。
- 浏览器可选择最大 25 MiB、4000 万像素的原图，本地压缩到长边 2048px 后上传；后端仍限制上传大小，不向前端配置模型或服务密钥。
- 套餐价格来自服务端；用户明确下单后打开支付宝收银台。跳转不表示到账，通过订单详情和余额确认。重试保留请求编号，不盲目重新购买。
- 健康检查与登录验收不代表模型生成已通过；真实生成与支付另行授权验收。

### 账户历史：接口与启用前置条件

独立作品页在登录后读取历史列表，支持游标分页、详情、压缩照片、完整诗词、可附照片的诗词分享 PNG 和显式二次确认永久删除。历史以统一账户归属，不局限当前浏览器或某个业务凭证。照片通过API 域名的凭证请求读取 Blob，缩略图进入视口附近才加载；登出/账户切换会取消请求、清除内容并释放对象 URL，浏览器持久存储不写入历史。

| 网站同源接口 | 官方上游 | 约束 |
| --- | --- | --- |
| `GET /web-api/history?limit=20&cursor=…` | `GET /v1/history` | `limit` 1–100，`cursor` 最长 512 字符，仅允许两个键且各出现一次 |
| `GET /web-api/history/{id}` | `GET /v1/history/{id}` | UUID，返回诗词详情、创建/到期时间及可用的 `photoName` / `photoDateTime` |
| `GET /web-api/history/{id}/image` | `GET /v1/history/{id}/image` | JPEG，最大 2 MiB，独立超时默认 15 秒（`WEB_HISTORY_IMAGE_TIMEOUT_MS`，最大 30 秒） |
| `DELETE /web-api/history/{id}` | `DELETE /v1/history/{id}` | 用户明确确认后发送，成功须返回 `{deleted:true}` |

所有历史接口仅接受已登录会话，BFF 使用该用户的业务 credential，不使用共享服务 token。其他路由仍禁止查询参数。图片代理禁止重定向，独立限制流式字节数和 MIME，不转发 Cookie、认证、缓存标识等上游隐私头；返回 `no-store` / `nosniff`。JSON 由 Go BFF 统一过滤敏感字段。

**后端未启用时历史返回 503，页面显示“历史尚未启用”，不阻止生成、当前作品下载和购买。** 404/410 表示记录已删除或过期。客户端不会仅凭生成成功宣称历史自动保存。

启用由服务管理员按 [Picpoet Server 历史说明与迁移步骤](../picpoet-server/README.md) 执行：

1. 先备份目标数据库，再按服务端 README 显式应用 `migrations/20261102_history.up.sql`；新建空库按其 `schema.sql` 流程准备。网站启动不会执行迁移。
2. 发布包含历史能力的服务端，先保持 `HISTORY_ENABLED=false`，核实官方生成依赖与数据库可用，并确保队列 worker 全部使用支持历史的新版本。
3. 管理员设置 `HISTORY_ENABLED=true` 后按服务端发布流程重启/滚动更新，再验证上述列表、详情、图片与删除接口。仅启用后新提交的任务开始收录。

停用时保留历史表与新版清理 worker，按服务端 README 处理归档/清理；普通停用不执行破坏性 down 迁移。永久删除清除服务端可读历史与任务结果副本，但数据库备份/WAL 的销毁受运维保留策略约束。本网站实现与自动测试不启动真实后端、不运行数据库迁移、不调用模型或支付。

### 登录态与后端职责

会话、加密存储、凭证刷新、注册与登录、订单幂等、邀请跳转和上游协议全部在 [picpoet-server](../picpoet-server/README.md) 实现。网站直接调用 API 域名的 `/web-api/*`，不直接调用 Dashboard API，不持有后端秘密；找回密码仅跳转到 Dashboard 网页。升级 Go BFF 时应保留旧会话数据库与配对密钥，按 server 的迁移说明执行。

## 统一发布清单

官网和历史 `/pages/` 下载页共用运行时代码：先匿名读取主清单，网络、状态、响应类型或清单校验失败才尝试备用。总预算 12 秒，主源最多等待 6 秒。有效但无安装包不触发切换；双源失败明确提示网络问题，不展示旧版本。每个安装包的默认下载域名跟随命中的清单，旁边的备用下载使用另一域名，同一 R2 对象键、文件大小及 SHA-256 不变。

预渲染只生成平台名称、锚点与加载状态。`test/fixtures/release-snapshot.json` 仅供离线契约检查与测试，不复制到交付目录，不作为线上数据或故障回退。官网旧 `/releases/stable.json` 与 `/pages/releases/stable.json` 均不再交付，也不重定向；使用旧清单地址的客户端需到官网手动更新。

清单包含 `schemaVersion: 1` 和六项 `platforms`。每个平台包含：

| 字段 | 内容 |
| --- | --- |
| `id` / `name` | 平台标识与显示名称 |
| `minimumSystem` | 已验收系统版本、发行版与架构要求 |
| `versionName` / `versionCode` | 展示版本与清单机器版本字段；Android 与实际包版本码一致，桌面采用同一语义版本映射作为清单排序值，未发布时为 `null` |
| `publishedAt` | ISO 8601 发布日期，未发布时为 `null` |
| `notes` | 更新说明字符串数组 |
| `artifacts` | 安装包数组，未发布时为空 |

Android 额外提供固定的 `applicationId: org.picpoet.app.android` 与 `minSdk`。每个安装包包含 `arch`、`format`、`url`、`sha256`、`sizeBytes`。`url` 使用不含凭据、可公开访问的 HTTPS CDN 绝对地址；安装包上传完成后再加入清单。`sha256` 是最终签名安装包的 64 位十六进制校验值，`sizeBytes` 为实际字节数。更新说明按纯文本展示。系统要求与说明以实时清单为准，内容与翻译源一致时才使用对应译文，清单更新可直接展示最新事实。

Android 当前已验证产物为 `arm64-v8a` / `apk`，仅在完整引擎及安装验收通过后声明其他 ABI。其余平台按最终构建填写实际架构；iOS 支持 `ipa`，HarmonyOS 支持 `hap` / `app`，Linux 支持 `tar.gz` / `AppImage` / `deb` / `rpm` / `zip`，macOS 支持 `dmg` / `pkg` / `zip`，Windows 支持 `exe` / `msi` / `zip`。包格式受支持表示页面可分发该格式，不代表当前已经生成该产物。

客户端发布流程先构建和验证安装包，再上传版本化对象。流水线使用客户端仓库的 `releases/<版本>.json` 生成正式版本化清单，由 CDN 回下载验证后条件更新 `stable.json`。网站不接收提交或部署通知；每次打开下载页都直接读取 R2。两个生产域名应匿名直接返回 `200 application/json` 与 `Cache-Control: no-store`。发布后用 `npm run releases:check:live` 校验两个下载域名的清单契约、一致性及对官网和历史父域的跨域许可。

新版 Android 正式构建从客户端 `android/packaging/release-config.json` 注入主备清单地址。在客户端目录执行 `python3 android/packaging/init-signing.py` 完成本机交互式证书初始化并加密备份后，执行 `python3 android/packaging/build-release.py`；已有签名配置时复用原签名。Flutter 源版本声明为 `version: 0.1.4` 时，Android 系统必需的整数字段按 `主版本 × 1000000 + 次版本 × 1000 + 修订版本` 自动生成，结果为 `1004`；界面与下载路径显示 `0.1.4`。次版本和修订版本各小于 1000，生成值为正整数且不超过 2100000000。桌面清单的 `1004` 是发布排序值，区别于可执行文件自身的平台版本资源。

GitHub Release 保留三平台聚合候选 `stable.candidate.json` 和完整的 `stable.json` 供核验；生产网站不直接访问 GitHub。Android 自动检查滚动 24 小时最多一次，手动检查可再次提示已忽略版本。用户确认后由浏览器下载、系统完成安装；同包名、同签名且新版本对应更高的系统版本码才能覆盖升级。首次从调试签名迁移到正式签名需另行处理数据备份。签名细节见 [客户端 README](../picpoet-app/README.md)。

## ESA Pages

- 静态页面、JS/CSS、字体和图片 → Pages；清单与安装包 → R2 主备下载域名，无需独立清单中继。
- 浏览器直接请求 `https://picpoet-api.jqknono.com/web-api/*` → Go BFF；邀请链接使用 API 域名并跳回官网登录页。

### Website 联调端口冲突处理

网站默认端口为 `18090`。一键联调启动时若该端口被占用，仅向当前用户的 TCP 监听进程发送 TERM，等待 5 秒后仍未退出则发送 KILL；不会终止整个进程组。其他用户的进程、无法识别或回收后仍占用的端口会报错，保留现场。此操作可能中断同一用户的其他项目；仅 website 端口启用此策略，其他后端端口继续保留占用进程。需要 Linux pidfd 支持及 `lsof`。已受管理且健康的 website 进程正常复用。旧 `8090` 进程不受影响。

### 分享图选项

下载和系统分享使用 `原图文件名（仅去掉最后一个扩展名）_picpoet.png`，例如 `春山.清晨.jpg` → `春山.清晨_picpoet.png`。不含路径，替换不合法字符；没有可用原名则用 `PicPoet.png`。优先读取 JPEG、PNG、WebP 原图的 EXIF `DateTimeOriginal`（含亚秒、`OffsetTimeOriginal`；没有时区按客户端本地时间解释）。GIF 无标准 EXIF，或拍摄时间不可用时，回退到原 `File.lastModified`；都缺失则不写日期。输出 PNG 使用标准 `eXIf` 块保存该时刻（保存原拍摄钟表时间及其偏移；仅有文件修改时间或 UTC 历史时使用 `+00:00`），不复制位置或设备信息。取消附图不会移除原文件名和日期。相册是否识别 PNG 拍摄时间取决于软件；浏览器无法指定下载文件在操作系统中的修改时间。

`POST /web-api/generations` 的 multipart 在独立文本字段 `photoName`（清理后的原文件名，含原扩展名，最多 255 UTF-8 字节）和 `photoDateTime`（带时区的 RFC 3339，保留拍摄时的偏移和亚秒；只有绝对时刻时用 `Z`）传递可用值；`image` 仍是重编码的 `photo.jpg`。重试复用任务快照；恢复任务和作品详情分别读取 `/web-api/generations/{id}/result`、`/web-api/history/{id}` 的同名字段，不使用当前选择的其他照片或作品创建时间，不回填缺失的历史元数据。原图字节不进浏览器持久存储。

在线创作或打开「我的作品」时，有对应照片时默认勾选“附加照片”和“铺满照片”。横图及方图在诗板上方占满卡片宽度，照片区域约为 16:9；竖图使用等宽双栏，左侧照片与右侧诗板等高。默认等比居中裁切以铺满照片区域；关闭“铺满照片”则完整居中显示照片，允许留白，位置不变。取消“附加照片”只导出诗词卡，“铺满照片”不可用，不影响邀请二维码选项。恢复任务没有对应本地照片、或历史照片不可用时，不显示照片选项，仍可导出诗词。照片合成在浏览器内完成，不额外上传。

创作结果与历史作品导出提供默认勾选的“附加邀请二维码”。取消勾选时弹窗以独立朱砂色奖励区突出“获赠 3 次创作”，并说明每位好友扫码注册成功后的奖励条件；不在页面增加常驻奖励提示。确认后重绘无二维码图片，也可保留二维码。每份新作品恢复默认选择；预览和下载始终使用同一版本图片。
